Matt Pocock Skills — Collection Analysis

Comparative capture of the public mattpocock/skills repo — a set of Claude/agent skills authored by Matt Pocock (Total TypeScript). Each note records what the skill does, its key mechanism (the part worth stealing), when it fires, and how it relates to this vault’s owned skill toolkit under skills.

Scope: 25 of the repo’s 29 skills — all active + in-progress. The 4 deprecated skills (design-an-interface, qa, request-refactor-plan, ubiquitous-language) were excluded by design. Captured 2026-06-08 against HEAD; this is a time-sensitive snapshot of an evolving repo.

Headline finding: the two collections barely overlap. This vault’s skills are thinking / verification / cognitive-burden tools; Pocock’s are engineering-workflow tools (TDD, triage, PRD/issue generation, debugging, repo setup). So 21/25 are novel (new capability area), and only the 4 below are flagged as direct adoption-candidates — novel and worth considering for the owned set.

Implementation backlog: adoption-plan — actionable grafts of these mechanisms onto specific owned skills, with a resume point and recommended order.

Recurring mechanisms worth stealing

The cross-cutting patterns that repeat across the collection — the real harvest for “further analysis”:

  1. One-question-at-a-time grilling (grill-me, grill-with-docs, triage, setup-*) — strict turn discipline, a recommended answer attached to every question, and “explore the codebase instead of asking when the answer is there.” More disciplined than the owned clarify-first’s batched AskUserQuestion.
  2. Vertical slices / tracer bullets (tdd, to-issues) — explicitly ban “horizontal slicing” (all tests then all code) in favor of thin end-to-end slices.
  3. Durability over precision in written artifacts (triage, to-prd, to-issues) — an anti-staleness rule: briefs/PRDs describe interfaces and behavior, never file paths or code snippets (except prototype-derived shapes), so they don’t rot.
  4. CONTEXT.md glossary + ADR as shared state (grill-with-docs, improve-codebase-architecture, to-prd, setup-*) — a persistent project vocabulary and decision log that multiple skills read and write, with a three-gate ADR test (hard-to-reverse, surprising, real trade-off).
  5. Re-read the file from disk before every append (writing-fragments, writing-beats, writing-shape) — preserves the user’s mid-session manual edits; never overwrites.
  6. Context isolation via parallel sub-agents (review, improve-codebase-architecture) — separate questions into disjoint sub-agent contexts so they can’t cross-contaminate or mask each other.
  7. Throwaway artifacts with capture-then-delete (prototype) — build to answer one question, record the answer durably, then delete.
  8. Guardrails as hooks, not instructions (git-guardrails-claude-code, setup-pre-commit) — enforce safety via PreToolUse / pre-commit hooks the harness runs, not prose the model may ignore.
