Skill: pr-contract

Assemble a PR title and description following the four-part PR contract — intent (the why, plus rejected alternatives), proof (only checks actually run; unrun listed as unrun, never claimed), provenance (what is AI-authored, what a human has reviewed), and review focus (risk-ranked spots needing human judgment) — from the diff, commit trail, and session evidence. The author-side counterpart of ai-diff-judgment: that skill consumes intent artifacts to judge a diff; this one produces them. Generative, portable to any repo.

When to use

  • Opening a PR — “open a PR”, “create a PR for this”, before gh pr create on any non-trivial diff
  • “Write the PR description”, “describe this change”, “write up this PR”
  • Retrofitting a description onto an existing PR whose description is empty or evidence-free
  • Ending a session whose branch someone (or some agent) will review without the session’s context

Skip when:

  • Judging whether an AI-authored diff should merge — ai-diff-judgment
  • Finding defects in a diff — lean-review or the built-in /code-review
  • Briefing a future agent to continue work — handoff (same session-evidence mining, different audience)
  • Commit messages — PR-granularity only

Why it exists

Review quality is capped by what the reviewer is handed: with an evidence-free description they reverse-engineer intent from the diff, spend attention uniformly instead of where risk sits, and can’t calibrate scrutiny to provenance. The contract idea (Osmani 2026, via ai-assisted-code-review) fixes the hand-off: intent gives the frame to judge against, proof separates verified from unverified claims (with a hard no-fabrication rule — an unrun check is listed as unrun), provenance tells the reviewer whether AI-diff scrutiny applies, and risk-ranked review focus points limited attention at the hunks that need judgment. It also closes a catalog gap: /ai-diff-judgment treats a missing intent artifact as a finding, but until this skill nothing on the shelf produced one.
