Skill: bias-scan-prompt

Scan a prompt (draft or already-written) for input-side framing bias before it’s sent to a model or baked into a spec.

When to use

  • High-stakes prompts you’ll act on the result of (specs, subagent briefs, research queries that drive decisions)
  • Prompts about to be baked into a skill body, system prompt, or recurring agent
  • Reviewing an existing prompt that’s been producing characteristically wrong output

Skip when:

  • Conversational, low-stakes prompts
  • Prompts whose output you’ll obviously sanity-check anyway
  • The artifact is an output, not a prompt (use /bias-scan-ai or /bias-scan-human)

Why it exists

Input framing constrains output more than the model does. Leading questions, embedded anchors, single-anecdote generalization, dispositional framing, hot-state drafting, and ruled-out alternatives bake bias into the answer before the model sees it. A scan at Pass 1 of the verification protocol catches this before the bias propagates downstream and gets re-laundered through fluent prose.
