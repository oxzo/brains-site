Skill: skill-trigger-eval

Runner for the catalog’s trigger evals: strips the answer key from a skill’s co-located eval/trigger-eval.md, routes each should-fire / should-not-fire query cold in a fresh-context subagent (via which-skill against the live catalog), then scores the actual pick against the ground truth. The empirical counterpart to skill-trigger-audit — the audit predicts match from the description statically; this measures what fires. Trigger-axis sibling of skill-output-eval, which runs the output eval.md.

When to use

  • After editing a skill’s description (retrieval regression check)
  • Before publishing or exporting a new skill with a trigger eval — confirm it fires on its jobs and stays off its siblings
  • After a frontier-model change, on the trigger-eval-covered subset — the catalog’s routing benchmark
  • When a skill is reported to misfire and a trigger eval exists

Skip when:

  • No persisted set exists — use /skill-trigger-audit (static prediction) or author a set first per skill-eval-format (trigger bullet)
  • The question is what the skill produces once it fires — /skill-output-eval
  • The question is static body/contract quality — /skill-quality-audit

Why it exists

Axis 9 of /skill-quality-audit reported trigger-eval existence but nothing ran the sets, and /skill-trigger-audit only predicts firing from the description — a prediction never checked against an actual cold routing. So a description could be edited (as the six code-structure scans were, 2026-07-22) on faith that the right queries still fire and the wrong ones still miss, with no empirical signal. This runner closes that loop with the same discipline as the output-eval runner: fresh-context execution, answer-key isolation (anchor-span and routes-to columns stripped, queries interleaved and unlabeled), verbatim collection, and a verdict that separates a description defect (route the surgical edit to /skill-trigger-audit) from an eval defect (an ambiguous query or wrong predicted sibling — fix the set). Batched single-subagent routing is the lightweight default; per-query isolation is the higher-fidelity fallback.
