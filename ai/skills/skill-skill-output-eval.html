Skill: skill-output-eval

Runner for the catalog’s output evals: stages a skill’s fixtures into a temp dir, executes each case in a fresh-context subagent, then grades mechanical checks before judge checks against the planted-finding labels in the skill’s co-located eval/eval.md. Completes the audit family — skill-quality-audit reads the body, skill-trigger-audit reads the description, this one executes the skill and scores the output.

When to use

  • After substantially editing the body of a skill that has an eval (regression check)
  • Before exporting a skill outside the vault, when an eval exists
  • After a frontier-model change, on the evaled subset — the catalog’s model benchmark
  • When a skill triggers fine but its output feels weak and an eval exists

Skip when:

  • The question is whether the skill fires (use /skill-trigger-audit) or whether its body is well built statically (use /skill-quality-audit)
  • The skill has no eval/eval.md — the runner refuses; author the eval first per skill-eval-format
  • You want to write an eval — the format note owns authoring; this skill only runs

Why it exists

The catalog audited structure and triggers but never measured outputs: a skill could pass both audits and still pad findings on clean artifacts or miss planted problems — and body edits shipped with no regression signal. Golden reference outputs were rejected as the grader (free-form prose; similarity scoring rewards mimicry), so the ground truth is planted-finding fixtures plus binary contract checks, with mechanical checks (greps, counts) anchoring the LLM-judge ones. The runner’s job is the discipline that makes a score mean something: fresh-context execution, label isolation (staged fixtures, no eval.md in the brief), verbatim collection, mechanical-first grading, and the label-gap rule so the eval improves instead of punishing the skill for being right.
