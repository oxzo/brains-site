Skill: option-premium-check

Scan a proposed action, a chosen path, or a list of deferred-but-unresolved items for flexibility-burning commitments (irreversible moves where an equal-EV reversible alternative exists) and optionality-hoarding patterns (deferred items whose carrying cost has overtaken the preserved option’s value — Pandora override). Claude names options-preserved, options-destroyed, and concrete carrying-cost mechanisms from the artifact; the user supplies felt lock-in pressure via AskUserQuestion. Mismatch between the formal option structure and felt lock-in surfaces the flags. Returns flags with implied next actions — take the flexibility-preserving alternative, or close the held-open option in one direction.

When to use

  • A proposed action is being framed as obvious or low-cost but you suspect it’s a one-way door
  • Two paths look roughly equivalent on expected payoff but you can’t tell which preserves more flexibility
  • A list of deferred items in a project, commitments log, or backlog has been sitting unresolved for a week or more
  • A roadmap branch point or ADR is approaching commit
  • Before a planning block where multiple lock-in moves are queued (schema decisions, API surface, naming conventions)
  • After a stretch of optionality-preserving moves, as a check on whether you’ve drifted into optionality hoarding

Skip when:

  • The queue’s failure mode is invisible per-week decay (use /whittle-scan — different lens on the same item type)
  • The artifact is a single draft needing adversarial review (use /red-team)
  • The question is about forward consequences across actors and time horizons (use /second-order)
  • The estimate to correct is numeric (use /reference-class)
  • The artifact contains no decision and no deferred-item list
  • You’re depleted — the option-structure enumeration is deliberation-heavy

Why it exists

The two failure modes are symmetric and both invisible to intuition. One-way-door blindness — committing to a path that destroys options when an equal-EV alternative would have preserved them. Naive expected-value calculation under-counts variance; flexibility has positive value under uncertainty (the option premium), and the premium rises with uncertainty — the opposite of how intuition treats variance. Optionality hoarding — keeping an option open at a carrying cost that exceeds its preserved value, dressing avoidance as prudence. Deferring commitment delays integration, blocks downstream work, and creates drift between artifact and world.

The skill’s most insidious failure mode is reproducing optionality hoarding via the scan itself — “preserve all options pending further analysis” is exactly what it exists to counter. The constraint that every flag must point at a specific next action (close the option, take the preserving alternative, or accept the lock-in explicitly) is the structural guard against that drift. The Step 0 routing discriminator (decay-dominant items → /whittle-scan; blocked-downstream-work-dominant items → stay here) prevents cross-skill cannibalization on deferred-list artifacts where both lenses would otherwise fire. The MEDIUM calibration anchor on Q3 (felt lock-in) — requiring the user to name one concrete reversal scenario before MEDIUM is recorded — guards against MEDIUM-default drift.
