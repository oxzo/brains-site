Skill: error-topology-scan

Diagnose how failures move through a codebase: a swallow census (caught and neither decided nor re-raised — log-and-continue included), a wrap-and-layer test on representative failure paths (more than two wraps between origin and handling layer is ceremony; a catch at a layer that can’t decide anything is wrong-layer), and Ousterhout’s define-out test (could a small interface change make this error a non-event?). Emits a markdown report to the OS temp dir with named-but-not-designed repairs, and stops at the design boundary — /grill designs the define-out.

A failure-path lens on the same static structure skill-deepen-architecture scans: error surface is interface width. A module whose callers must know five exception types is wider than its signatures admit, and a layer that catches everything but decides nothing is a shallow module wearing a try/catch.

When to use

  • Error handling feels scattered: caught everywhere, handled nowhere, logs full of noise
  • Auditing failure paths before hardening a service or adding retries
  • Repeated incidents where a failure was “logged but nothing happened”
  • The user names “swallowed exceptions”, “error handling mess”, or “who actually handles this?”

Skip when:

  • The question is module depth in general — /deepen-architecture
  • You want correctness review of one diff — /lean-review; an AI-authored merge call — /ai-diff-judgment
  • You want consequence simulation of a decision — /second-order
  • You want runtime resilience testing (chaos, load) — out of scope for a static scan

Why it exists

Error-handling sprawl is the failure mode where every layer catches, wraps, and logs while the actual decision — retry, degrade, abort, tell the user — is made nowhere; it hides from diff review because each individual catch block looks responsible. The scan’s two calibration guards define its character: logging is not handling (a log-and-continue is a swallow whatever the log level), and top-level boundaries that catch-all-and-report are the sanctioned pattern, not a finding — the scan hunts mid-layer swallows, not try/catch as such. The define-out test adds the one genuinely architectural move in error handling: redesigning the interface so the error case stops existing.
