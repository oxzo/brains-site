Skill: churn-hotspot-scan

Mine a repo’s git history for empirical structure problems: hotspots (high churn × high complexity-proxy files) and change coupling (file pairs that co-change in the same commits across module boundaries — the shotgun-surgery signal). Evidence is computed from git log, not judged by reading code; a cold-complexity discount strikes big-but-unchanging files so the scan never degrades into a big-file detector. Emits a markdown report to the OS temp dir with three honest verdicts: ranked candidates, clean (“change is evenly spread”), or insufficient history.

The evolutionary sibling of skill-deepen-architecture and skill-dependency-flow-scan — the only scan in the family that adds a new evidence source (commit history) rather than another lens on the static tree. In the Tornhill “code as a crime scene” tradition: history says where, the static scans say what to do there. Run it first to prioritize them on a codebase too large to scan whole.

When to use

  • Deciding where refactoring effort would actually pay off, with evidence instead of opinion
  • “Why does every change to X also touch Y?” — suspected shotgun surgery
  • Prioritizing /deepen-architecture or /dependency-flow-scan on a large codebase
  • Sizing maintenance cost: which files eat the team’s commits

Skip when:

  • You want the why behind a hot module’s cost — /deepen-architecture on the flagged subtree
  • The question is import direction or cycles — /dependency-flow-scan
  • System behaviour over time (loops, delays) — /structural-trace
  • The target isn’t a git repo, or history is too thin to rank (the skill reports “insufficient history” rather than ranking noise)

Why it exists

Refactoring effort is chronically intuition-led: teams polish the code that annoys them while the files that actually eat the commit budget go unmeasured — and static analysis can’t correct this, because a structurally ugly module that never changes costs nothing. Git history is the only evidence source that prices structure problems by what they actually cost, and no skill in the catalog consumed it. This scan converts that history into ranked, threshold-stated findings (window, coupling ratio, and exclusions declared in the report’s method line, per the vault’s no-hidden-provenance discipline) and routes each candidate to the static scan that can explain it.
