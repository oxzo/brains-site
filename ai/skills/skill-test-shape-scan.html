Skill: test-shape-scan

Read a test suite as architecture evidence: an interface-fidelity census (tests importing or patching past the declared interface), a mock-density distribution (heavy-mock clusters reveal wide implicit interfaces), and a seam-alignment test that classifies every doubled dependency by /deepen-architecture’s four seam categories — doubling an in-process dependency and unit-testing against a live true-external are the two convictions. Findings attach to the module whose seam is wrong, not the test — the suite is the witness, not the culprit. Emits a markdown report to the OS temp dir; does not write or fix tests.

The test-side mirror of skill-deepen-architecture: that skill’s battery says the interface is the test surface; this measures how far the actual suite is from that ideal and feeds its strong findings back as pre-qualified deepening candidates. The shared verbatim glossary (module, interface, seam, adapter, the four seam categories) is what lets the two reports be read together.

When to use

  • Tests break on every refactor even when behaviour didn’t change
  • A suite drowning in mocks, or “we can’t test this without patching internals”
  • Judging testability before restructuring modules — evidence for where seams are wrong
  • After /deepen-architecture flags a module, to corroborate from the test side

Skip when:

  • Judging module depth from production code — /deepen-architecture directly
  • Reviewing one diff and its tests for correctness — /lean-review; AI-authored merge call — /ai-diff-judgment
  • Writing new tests or fixing brittle ones — downstream execution
  • Diagnosing runtime flakiness (timing, ordering) — not a static-shape question

Why it exists

A test suite is the cheapest architecture probe a codebase carries — every mock is a confession about what the module under test really needs, and every internals import is a measurement of the gap between declared and real interface — yet suites are conventionally judged only by coverage, which is structure-blind: a suite can pass at 90% coverage while coupling every test to internals the next refactor must break. Two stances keep the scan honest: it never blames the tests (findings attach to modules; scolding test authors misses the signal), and it never moralizes coverage (a well-shaped thin suite beats a structure-blind thick one — coverage is someone else’s axis).
