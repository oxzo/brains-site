Skill: context-budget-scan

Three-mode scan of context-window economics — artifact (a static prompt, agent brief, CLAUDE.md fragment, or system-prompt section), architecture (an agent loop or design doc), or session (a conversation transcript) — for cache-unfriendly ordering, lost-in-middle placement, verbatim-instead-of-reference inclusion, memory-hierarchy misses, tool-output bloat, cross-layer redundancy, and missing compaction strategy. Operates on the token-economy axis: how the context budget is being spent against what it buys.

When to use

  • Before issuing a long prompt or agent brief that will run many times — cost compounds
  • Before deploying or substantially editing an agent loop / system prompt — Signal 7 (missing compaction) is cheapest to catch at design time
  • Before growing a persistent layer (CLAUDE.md, .claude/rules/*.md, MEMORY.md) — Signal 4 (memory hierarchy) findings here pay every turn forever
  • When a Claude Code session has crossed a context-pressure stage (microcompaction triggered, response latency rising, output quality dropping)
  • After a session that produced poor output, to retrospectively identify the bloat

Skip when:

  • Short prompts (<500 tokens, single concern, no cache implication, no persistent layer) — token-economy is not the bottleneck
  • The question is comprehension (use density-scan)
  • The question is plan structure (use plan-split-scan)
  • The question is per-output verification (use reviewers-map)
  • Throwaway / exploratory work

Why it exists

Prompts and sessions grow monotonically — each addition feels like “just one more thing” until token cost, response latency, attention degradation, or autocompact damage the output. The failure is silent: each addition was individually justified, the aggregate violates cache boundaries, scatters load-bearing content into the lost-in-middle zone, duplicates persistent memory in-turn, or has no plan for what to evict. The scan names the seven structural signals (and the per-mode refuse-to-scan floors) so the budget decision is auditable, not vibes-based. Distinct axis from /density-scan (comprehension), /plan-split-scan (executor structure), /reviewers-map (output verification) — a prompt can be density-clean and budget-bloated, or vice versa.
