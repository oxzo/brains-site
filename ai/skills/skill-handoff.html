Skill: handoff

Compacts a conversation into a portable handoff document a fresh agent (or a future session) can read to continue the work without re-deriving context. The output is a single file written outside the workspace (OS temp dir), tailored to what the next session is for, with four low-freedom construction rules: temp-dir-not-workspace, a mandatory suggested-skills routing section, dedup-by-reference, and a secret-redaction pass. Produces a continuation doc, not an execution. The next-agent-facing counterpart of commitment-ledger — same gather step, inverted audience.

When to use

  • A session is long enough that compaction or a fresh session is imminent and the work isn’t finished
  • Passing work to another agent, or to a future session, without losing decisions and open threads
  • You want the next session pre-routed to the right skills
  • Handing off across a context-window boundary where the raw transcript won’t survive

Skip when:

  • You want a human-facing closeout audit of what was agreed and what went unverified — that is /commitment-ledger
  • You’re extracting transferable lessons from a completed cycle (decision vs outcome quality) — /retrospective
  • You’re diagnosing why a prompt or session burns tokens — /context-budget-scan
  • The session is short, self-contained, and crosses no context boundary

Why it exists

The owned toolkit had no AI-to-AI continuation artifact. commitment-ledger is the closest sibling — both produce a session-closeout artifact from the same gather step (git diff + conversation scan for decisions, open threads, deferred items) — but the ledger’s reader is the human (an accountability audit: what did I agree to, which claims went unverified), while handoff’s reader is the next agent picking the work up cold. That audience flip brings three mechanisms the ledger lacks: a suggested-skills routing section (the next session starts pre-routed, not cold), a dedup-by-reference rule (anything already in a note/plan/commit is linked by path, never re-summarized — keeping the doc lean and staleness-free), and a temp-dir + redaction discipline (ephemeral, out of version control, secrets stripped).

It was authored as Option B of adoption-plan T3.2: a separate skill rather than a commitment-ledger mode. Same reasoning that split grill from clarify-first (T1.3): different audience, output, and trigger vocabulary make them different shapes, and the catalog factors by shape — folding a second audience into one skill is the “if a description leans on ‘or’, split it” anti-pattern. Unlike the source, handoff carries no re-read-from-disk discipline: it writes a fresh temp file each invocation rather than appending to a shared log. Source mechanism: the public handoff skill in mattpocock/skills (its four construction rules adopted near-verbatim, adapted to reference vault notes/plans/commits by path).

Built 2026-06-08 via /write-a-skill; structural and trigger audits run before publish.

Gate-first routing, added 2026-07-29 from field evidence. Rule 2 now requires looking for a check the receiving repo already enforces — test suite, mutation harness, CI, type checker — and naming it before any owned skill. The correction came from a run recorded in journal/skill-field-log.md: a handoff into a repo whose own harness gates every change routed the next session to four verification scans, and none of them fired, because the harness was the stricter test and that repo’s stated rule was that a fix without a mutation is one the harness cannot defend. The bias is structural rather than accidental — this section is written by a vault skill, so vault skills are its path of least resistance, and a routing list that looks thorough while pointing at the weaker tool is worse than an empty one. The gate line is the counterweight.
