Skill: ai-diff-judgment

Decide whether to merge an AI-authored git diff after green CI — the human-judgment layer machines can’t run. The organizing spine is intent: recover what the change was supposed to do (ticket → PR description + agent reasoning log → commits → diff self-evidence), decompose it into checkable clauses, and verify the implementation clause-by-clause. Around that spine it reads the test diff before the code diff (the highest-signal AI-specific check), hunts failure modes a passing suite can’t see (spec drift, goal substitution, test tampering, hollow coverage-theater tests, error-handling theater, deleted invariants), and rations depth by a trust-signal prior. Output is altitude-ordered — intent verdict before any Conventional-Comments line finding — ending in a six-way net-improvement decision (Ship → Reject) with hard escalation triggers.

When to use

  • An agent / Claude / Copilot / Cursor wrote the change, CI is green, and you must decide: merge, return to the agent, or escalate
  • “Did the agent actually implement the spec?” / “Can I trust this AI PR?”
  • Signing off agent output where the risk is plausible-but-wrong, not broken

Skip when:

  • Provenance-irrelevant correctness review → lean-review (cheap) or built-in /code-review (broad)
  • Verifying an AI text artifact’s claims → reviewers-map
  • Bias fingerprints in an AI artifact → bias-scan-ai
  • You need to run the change to confirm behavior → built-in /verify
  • CI is not green — the skill stops by design; fix the machine layer first

Why it exists

Counters automation-bias merging: AI code that passes every gate can still be internally consistent yet implement the wrong spec — tests check the inferred spec, not the actual one (evaluating-ai-code-beyond-tests). General review skills hunt correctness; nothing else makes intent fidelity the spine. It also carries an honest self-limit: an AI reviewer sharing a model family with the author has correlated blind spots, so it escalates readily and never claims to replace human architectural sign-off.

First live run (2026-06-05)

/ai-diff-judgment on the tikkuukko diff — 15 LOC / 3 files of uncommitted working-tree changes (boil-runtime.ts, boil.tsx, level1-cave.tsx). How each step played out:

  • Intent recovery fell to the lowest-priority source (diff self-evidence — no ticket/PR/commit message) and was presented back as an explicit assumption, exactly the fallback path the build-time dry-run forced into the skill. Three clauses recovered: animation-cycle bug fix (seed % 3 could never index a length-4 pose cycle), magic-number naming, redundant-condition cleanup.
  • Trust triage → low prior (small diff, existing patterns, 2 of 3 clauses behavior-preserving), so steps 9–10 ran as spot-check only. Total cost: ~4 tool calls — the depth-rationing did its job.
  • Verdict: Ship; clause table all-implemented; one non-blocking issue: (visible behavior change, project has no test suite → recommend /verify), one suggestion: (a useBoilFrame() hook instead of subscription-only useBoilSeed() + direct singleton read), one praise: (why-comment on SPIKE_HIT_H).

Calibration lessons:

  1. The grep-to-confirm discipline prevented a false positive. First instinct was to flag the direct Boil.frame read as the step-9 “React data-flow escape”; reading useBoilSeed’s implementation showed force-update reads of the singleton are the module’s established idiom — finding correctly demoted from issue: to suggestion:. Pattern-match alone would have shipped the false positive.
  2. The “assume CI green” premise is weak on hobby projects with no test infra — the skill noted it inline rather than pretending the machine layer existed. Watch whether this needs a first-class “no machine layer” branch if it recurs.
