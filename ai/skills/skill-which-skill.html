Skill: which-skill

Recommend which skill(s) from the local catalog to invoke given a situation, an artifact, or an intent. Returns 1–3 ranked candidates with quoted trigger phrases plus 1–2 rejected near-misses.

When to use

  • The catalog is too large to hold in your head and you want a routed recommendation
  • Two skills look adjacent and the choice between them isn’t obvious
  • You want the routing decision made explicit and auditable rather than silently picked
  • A skill recently misfired and you want to confirm the catalog still routes a class of requests correctly
  • Before publishing a new skill — alongside /skill-trigger-audit, check whether the new skill overlaps existing routes

Skip when:

  • The matching skill is obvious — just invoke it
  • The request is clearly outside the skill catalog (regular code edits, vault note authoring)
  • For built-in Claude Code commands (/init, /review, /security-review)

Why it exists

Claude already matches user phrasings against skill descriptions silently — picks one and runs. As the catalog grows, the silent pick becomes less reliable: descriptions overlap, user vocabulary drifts from skill vocabulary, two adjacent skills both plausibly fit. /which-skill makes that implicit routing visible. The output (ranked candidates with quoted trigger phrases and rejected near-misses) is an artifact the user can correct, and the rejection reasons teach the catalog — two-thirds of the value is in the near-misses, not the recommendation.

The skill is the dynamic counterpart to verification-stack-operational-map: the map is the static decision tree, /which-skill routes a specific request. Use the map when you can hold the catalog in view; use /which-skill when the catalog is too large or the choice is ambiguous.
