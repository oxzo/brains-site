Verification Stack Operational Map

What it is

A single decision tree across the 38 per-task skills installed in this vault (verification, ideation, planning, review, cognitive-burden, authoring-quality, valuation, and corpus-maintenance) — when to run which, in what order, what each catches the others miss — plus the meta-router /which-skill that selects among them. The skills exist; the integrated picture didn’t.

The 38 per-task skills (as of 2026-06-08, source: .claude/skills/ directory): ai-diff-judgment, assumption-reversal, bias-scan-ai, bias-scan-human, bias-scan-prompt, branch-resolve, calibration-loop, claim-function-scan, clarify-first, commitment-ledger, context-budget-scan, contradiction-scan, density-scan, disagree, falsifiability-scan, grill, handoff, intent-check, intent-fulfilment-check, lean-review, option-premium-check, persona-cluster-check, plan-options, plan-split-scan, red-team, reference-class, retrospective, reviewers-map, scamper, second-order, skill-quality-audit, skill-trigger-audit, staleness-decay-scan, starburst, structural-trace, task-decompose, whittle-scan, write-a-skill.

The 39th, /which-skill, sits outside the per-task taxonomy as a meta-router — given a request, it ranks 1–3 candidate skills with quoted trigger phrases and rejected near-misses. This map and /which-skill are complementary: the map is the static decision tree (read top-down to find an entry skill); /which-skill is the dynamic counterpart (describe the situation, get routed). At 38 per-task skills the catalog has outgrown casual scanning — in practice /which-skill is increasingly the working entry point, and this map is the auditable reference it routes against.

Revision history: first revision mapped 15 skills; the 2026-05-10 revision added claim-function-scan, density-scan, persona-cluster-check, skill-trigger-audit, and the /which-skill meta-router (19+1). This revision (2026-06-05) adds fifteen: the work-cycle set (intent-check, plan-options, plan-split-scan, branch-resolve, task-decompose, intent-fulfilment-check, retrospective), the request-side clarify-first, the code-review pair (lean-review, ai-diff-judgment), the token-economy context-budget-scan, the valuation pair (whittle-scan, option-premium-check), and the corpus-maintenance pair (contradiction-scan, staleness-decay-scan). The taxonomy grows from seven clusters to twelve. A same-day addendum (2026-06-05) adds skill-quality-audit (35+1) — the body/structure complement to skill-trigger-audit, built from the deep-research note skill-quality-criteria. A further revision (2026-06-08) adds three more, each folding into an existing cluster: grill (interactive plan interrogation → plan & decomposition), handoff (next-agent continuation → cognitive-burden, beside commitment-ledger), and write-a-skill (the generative front of the skill-authoring trio → authoring-side). 38+1. The twelve clusters absorb all three — no new top-level mode.

Why this exists

Two narrower maps already cover part of the surface:

  • bias-aware-verification-protocol — four-pass framework (/bias-scan-prompt → /bias-scan-ai → /disagree → /red-team) plus the orthogonal /bias-scan-human. Five of 38.
  • cognitive-burden-of-ai-use — three cognitive-burden counters (/reviewers-map, /commitment-ledger, /calibration-loop). Three of 38.
  • intent-to-retrospective-loop — the develop-and-verify loop across the seven work-cycle skills. Seven of 38.

Together: fifteen. The other twenty-three sit outside those anchors and have no shared decision surface. The existing notes also do not answer the cross-cutting question: which skill fits this exact moment?

The cost of not having this map is invocation-surface friction. Per cognitive-burden-of-ai-use (Lee et al., CHI 2025), the deliberate act of choosing to run a verification step is where verification dies. A decision tree replaces “remember which skill” with “what stage am I in.”

The skills, by purpose

Twelve functional clusters across the 38 per-task skills. A per-task skill belongs to exactly one — the cluster captures what mode the skill puts you in, not what topics it can touch. /which-skill is the meta-router and is described separately below; it does not belong to a cluster because it does not put you in a working mode — it picks one for you.

Pre-action clarification — request-side

The only cluster that runs before the task itself is settled. Single member by design — it has no neighbor in invocation shape.

  • /clarify-first — research-then-ground-then-ask protocol on a vague but load-bearing request: mine the conversation and codebase first, then ask multiple-choice questions where every option traces to a real finding. Counters ungrounded clarification (options confabulated from training-data priors).

Generative — pre-commitment ideation

Used before you have committed to a frame, an option set, or a problem definition. Output is divergent: alternatives, questions, frame breaks. None of these evaluate or select.

  • /assumption-reversal — surface 5 unstated assumptions in a problem; invert each as a one-line design brief. Frame attack.
  • /scamper — Substitute / Combine / Adapt / Modify / Put-to-another-use / Eliminate / Rearrange — structured divergent variants on a candidate idea.
  • /starburst — Who / What / Where / When / Why / How questions around an idea. Pre-commitment gap analysis.

Intent anchoring & loop closure — the cycle’s bookends

Bracket a work cycle: audit the goal before work starts, check the output against it after, convert the cycle into lessons. See intent-to-retrospective-loop.

  • /intent-check — four-axis test (form, completion-falsifiable, navigable, altitude) on a stated intent, goal, or objective. Counters theatrical intent — a goal too vague to anchor anything.
  • /intent-fulfilment-check — decompose the originating intent into clauses; mark each served / partial / substituted / unaddressed against the produced output; flag scope inflation. Counters silent goal-substitution. Requires both an intent and an output — route to /intent-check if the intent is missing.
  • /retrospective — convert a completed cycle into transferable lessons plus a resulting (process-vs-outcome) verdict; auto-feeds the calibration log.

Plan & decomposition — before execution

Operate on plans, not artifacts. Two generative (produce the plan), two diagnostic (audit it), one interactive (interrogate it).

  • /plan-options — generate 2–3 genuinely different candidate plans, each traced clause-by-clause to the intent, then collapse to one with the choice reason recorded. Counters median-collapse. Skips (and says so) on trivial tasks.
  • /task-decompose — decompose the chosen plan into tasks with a done-criterion + interface contract + risk-ordering at generation time. Refuses on routine work.
  • /plan-split-scan — scan a draft multi-step plan for five structural signals (concern count, state-carry depth, decision branches, verification seams, reversibility boundary); recommend split / consolidate / leave-alone. Executor-side load axis.
  • /branch-resolve — operationalize each unresolved decision branch: resolve up front, split at the determinant, or express as an IF-trigger-THEN-response implementation intention; hard split on branches with destructive downstream. Counters branch-collapse.
  • /grill — sustained one-question-at-a-time interview that walks an in-progress plan’s decision tree in dependency order, attaches a recommended answer to each question, and explores the codebase to settle a point rather than asking. Produces a resolved-decisions ledger, not an execution. The interactive member — distinct from the static scans, which read a finished draft.

Detection scans — bias fingerprints on a specific artifact

Each scans one axis of bias on one target.

  • /bias-scan-prompt — input-side framing in a prompt about to be sent. Pass 1 of the verification protocol.
  • /bias-scan-ai — output-side fingerprints in an AI-drafted artifact. Pass 2; full seven-check sweep, backed by ai-output-bias-fingerprints.
  • /bias-scan-human — full cognitive-bias catalog (sunk cost, confirmation, FAE, narrative fallacy, planning fallacy, anchoring, etc.) on a human-authored artifact. Orthogonal to the four-pass AI protocol.

Operationalization — claim triage, sharpening, numeric grounding

Take a draft and improve the testability or grounding of specific elements within it. Tag-and-fix shape, not whole-artifact verdict.

  • /claim-function-scan — triage claims into empirical / non-empirical / bundled. The actionable failure mode is the bundled case: an empirical claim wrapped in an identity or coordination frame, immune to challenge until split. Triage pass before /falsifiability-scan or /reviewers-map when claims may be bundled.
  • /falsifiability-scan — categorize claims by testability ([OP] / [DEFER] / [VAGUE] / [SEAL] / [PROB] / [DEFN]); operationalization checklist for the ones worth sharpening. Backed by falsifiability-claim-fingerprints.
  • /reference-class — apply outside-view forecasting to numeric estimates in a draft (durations, costs, sizes, percentages). Tag inside-view estimates against base-rate distributions. Backed by reference-class-forecasting.

Adversarial — post-draft

Run after a draft exists. Goal is to find it wrong, not improve it from inside.

  • /disagree — inversion drill on the most recent substantive assistant response. Argue the opposite. The variance under reframing is the calibration signal. Pass 3.
  • /red-team — adversarial critique of an artifact. Returns strongest objections, pre-mortem, weakest load-bearing claim. Pass 4.

Code review — diffs, not prose

The only cluster whose target is code. Pick by what question you’re asking, not by diff size alone.

  • /lean-review — token-frugal correctness review of the current diff: scope with --stat first, read only changed hunks, bounded severity · file:line findings. Provenance-irrelevant. The cheap default.
  • /ai-diff-judgment — post-green-CI merge judgment on an AI-authored diff: recover the originating intent, verify it clause-by-clause, read the test diff before the code diff, hunt spec drift / hollow tests / test tampering; altitude-ordered verdict ending in a net-improvement decision. Counters automation-bias merging.

Built-in neighbors (not vault skills, but in the same routing space): /code-review (maximum-coverage correctness, effort-tiered) and /verify (run the app and observe behavior — the empirical complement both vault skills explicitly defer to).

Forward and structural — action / system tracing

These don’t scan an artifact for bias — they trace a behavior or action through time and structure.

  • /second-order — neutral forward simulation of a proposed action’s consequences across three orders, sign-neutral. Pairs with /red-team (which weaponizes the unfavorable branches).
  • /structural-trace — stocks-flows-feedback diagnosis of a recurring pattern. Senge archetypes, Meadows leverage points. Diagnostic, not prescriptive. Counters dispositional explanation (blaming actors when structure is the cause).

Valuation — queues, options, commitments

Price what the other clusters don’t: the cost of not acting, and the flexibility a choice destroys.

  • /whittle-scan — surface queue items whose cost-of-inaction is invisible per-week (decay valuation): dated commitments and forecast-resolution-dates rotting quietly.
  • /option-premium-check — sign a proposed action or deferred-item list as flexibility-creating / flexibility-burning / dominant / optionality-hoarding; flags one-way doors with equal-payoff two-way alternatives, and deferral sets whose carrying cost exceeds the preserved option’s value.

Cognitive-burden counters — per-output / per-session / multi-session

Address the load of verification and continuation, not the verification itself. Each operates at a different granularity.

  • /reviewers-map — per-output verification map: load-bearing claims tagged [V] / [U] / [I], least-confident spots, five-minute check list, what was not done. Lighter than /bias-scan-ai. Counters cognitive decoupling.
  • /commitment-ledger — per-session closeout: files touched, claims accepted without verification, decisions, deferrals, what to check first tomorrow. Counters accountability without authorship. Optionally appends to journal/commitments-log.
  • /handoff — per-session continuation doc for the next agent or session: compacts the conversation into carry-forward state (decisions, open threads, a mandatory suggested-skills routing section), dedup-by-reference, written to the OS temp dir out of version control. The next-agent-facing counterpart to /commitment-ledger (human-audit-facing). Counters continuation amnesia across a context boundary.
  • /calibration-loop — multi-session loop. record captures a binary prediction with resolution criterion; resolve closes predictions whose deadline has passed; review reports Brier score and calibration buckets. Reads/writes journal/calibration-log. Counters uncalibrated confidence.

Authoring-side scans — prose form, invocation surface, token budget

These mostly don’t verify the content of an artifact — they audit the form, the invocation surface, and the budget. The cluster also holds one generator (/write-a-skill) that produces a skill the two audits then check. Each targets an axis where a fluent-looking artifact silently fails to do its job.

  • /density-scan — information-density failure modes in prose: surprisal spikes, sentence-length monotony, propositional density mismatched to channel, long-distance dependencies, the “shorter is better” compression trap. Reader-comprehension axis.
  • /context-budget-scan — token-economy scan in three modes (artifact / architecture / session): cache-unfriendly ordering, lost-in-middle placement, tool-output bloat, missing compaction strategy. Explicitly a different axis from /density-scan — what the artifact costs the model, not the reader.
  • /persona-cluster-check — for “You are an expert X” primes, surface the cluster of register, defaults, and biases the persona invokes from training data, then check fit to the actual job.
  • /write-a-skill — generator for a new SKILL.md from a capability description: produces the frontmatter (third-person what+when description), body structure, and output contract. The generative front of the skill-authoring trio — feed its output to /skill-trigger-audit then /skill-quality-audit before publishing.
  • /skill-trigger-audit — audit a SKILL.md description for retrieval-match quality (will the skill fire on the queries it was built for?).
  • /skill-quality-audit — deep structural audit of a SKILL.md body and metadata: description↔body truthfulness, procedure executability, output contract with a reachable clean verdict, catalog-sync integrity. The complement of /skill-trigger-audit — that one asks “will it fire”, this one asks “when it fires, is it built to do its job”.

Corpus maintenance — cross-note scans

The only skills that ingest more than one note and reason over the set. They counter the silent decay an append-mostly vault accumulates (see knowledge-base-entropy). Report-only: ledger or action table, never a rewrite.

  • /contradiction-scan — surface note-pairs that silently disagree about the same empirical claim (distributed inconsistency); emits a conflict ledger with both claims quoted.
  • /staleness-decay-scan — surface time-sensitive notes whose perishable claims have aged past a volatility-adjusted half-life; ranked re-verify / re-date / archive / promote-durable table. Owns perishable static facts; dated commitments go to /whittle-scan.

Meta-router — selection across the catalog

Outside the per-task taxonomy. Operates one level above: given a request, returns the per-task skill(s) to invoke.

  • /which-skill — given a situation, artifact, or intent, ranks 1–3 candidate skills with quoted trigger phrases, one-line rationales, and what each won’t do — plus 1–2 rejected near-misses. Returns a “no skill fits” verdict when honest.

Common chains — in what order

Eight chains cover most non-trivial work. Skills are listed in execution order. Stop early if the artifact is exploratory; run the full chain only at high stakes.

Chain 1 — Pre-commit an AI-drafted artifact

/bias-scan-prompt  →  drafting  →  /reviewers-map  →  /bias-scan-ai  →  /red-team  →  /calibration-loop record
   (Pass 1)                         (light, fast)      (deep, 7-check)   (if high-stakes)   (if a prediction)

/reviewers-map is the cheap default; /bias-scan-ai is the deep dive. Don’t run both by default — pick by stakes. Add /falsifiability-scan if the draft has load-bearing prose claims; add /reference-class if it has numeric estimates.

Chain 2 — Pre-commit a human-authored synthesis

drafting  →  /bias-scan-human  →  /claim-function-scan (if mixed)  →  /falsifiability-scan  →  /reference-class (if numbers)  →  /red-team

/bias-scan-human covers the cognitive-bias side; /claim-function-scan triages bundled claims before they reach the next pass; /falsifiability-scan and /reference-class cover the operational-shape side; /red-team covers the adversarial side. Skip /claim-function-scan if the artifact is purely technical or purely narrative.

Chain 3 — Pre-commit a decision

/starburst  →  /second-order  →  /option-premium-check (if one-way door)  →  /red-team  →  /calibration-loop record
  (gaps)        (consequences)     (what flexibility it burns)               (objections)    (close the loop)

/starburst surfaces what you do not know; /second-order traces the cascade neutrally; /option-premium-check prices the reversibility; /red-team weaponizes the unfavorable branches; /calibration-loop record makes the decision a falsifiable prediction.

Chain 4 — Diagnose a recurring problem

/structural-trace  →  /second-order
  (diagnose the         (test the proposed action through the
   standing system)     structure just diagnosed)

Don’t reverse the order. You need the structure first, or the action’s consequences are traced through the wrong system.

Chain 5 — Break a stuck frame

/assumption-reversal  →  /scamper (or) /starburst
  (frame attack)         (variants)     (gaps)

After /assumption-reversal, pick whichever next step matches what you have less of — options or questions.

Chain 6 — Authoring quality on a prompt or skill artifact

[draft prompt or SKILL.md]  →  /persona-cluster-check (if persona prime)  →  /bias-scan-prompt (if runnable)  →  /density-scan  →  /context-budget-scan (if it will run many times)  →  /skill-quality-audit + /skill-trigger-audit (if SKILL.md — body/structure, then trigger surface)

Runs orthogonally to chains 1–5 — they verify content, this chain checks form, budget, and invocation surface. Apply the relevant content chain first, then run this on the final draft.

Chain 7 — Full work cycle (develop-and-verify loop)

/clarify-first (if request vague)  →  /intent-check  →  /plan-options  →  /plan-split-scan (+ /branch-resolve on flagged branches; + /grill to interrogate the plan interactively)  →  /task-decompose  →  [execute]  →  /lean-review or /ai-diff-judgment (if the output is a diff)  →  /intent-fulfilment-check  →  /retrospective

The skeleton of intent-to-retrospective-loop. Most stages are skippable on routine work — /plan-options and /task-decompose refuse trivial tasks by design; the load-bearing minimum is /intent-check at the front and /intent-fulfilment-check at the back, which together catch silent goal-substitution.

Chain 8 — Corpus maintenance pass

/staleness-decay-scan  →  /contradiction-scan  →  /whittle-scan
  (which dated claims        (which note-pairs          (which dated commitments
   expired silently)          silently disagree)          are decaying in the queue)

Periodic, vault-level. The three are disjoint by design: perishable static facts / cross-note disagreement / dated commitments. Run when a fast-moving domain shifted or before relying on an aging cluster in new work.

What each catches the others miss — non-overlap

The skills tile the surface; each row is a different cut. The matrix is non-strict — /red-team partially overlaps /bias-scan-ai, /falsifiability-scan overlaps /bias-scan-ai rule 4. The point is that no skill is redundant: each owns a primary axis.

Anti-patterns

  • Map theater. Running every skill in every chain because the map says so. Per bias-aware-verification-protocol: “overhead unmatched to stakes is the main reason verification protocols get abandoned.” The same applies at this meta level — and applies harder at 38 skills than it did at 19.
  • Forcing a skill outside its cluster. /red-team is adversarial, not generative — running it for ideation gives objections to options that don’t exist yet. /starburst does not evaluate; it asks. /lean-review does not hunt intent drift; /ai-diff-judgment does not maximize correctness coverage.
  • Skipping the map. Picking by name-recognition (“/red-team sounds right”) instead of by trigger. The trigger language above is the entry point; the skill names are the exit.
  • Treating skill output as authoritative. Each skill is itself an AI output and is subject to the bias fingerprints /bias-scan-ai exists to detect. Skepticism does not bottom out. The map reduces friction; it does not produce correctness.
  • Letting the chain replace engagement. Running Chain 1 mechanically on an AI-drafted thesis without adjusting any probability table or rewriting any framing is the failure mode the augur project explicitly guards against. Skills do not substitute for substantive editing.
  • Map-as-end-state. This map is unmeasured opinion until someone actually scores artifacts before/after the protocol and produces a delta. Until then, treat the operational picture as a working hypothesis and revise when chains fail in practice.

Open questions for the next revision

  • Does the static map still scale at 38? The 2026-05-10 revision asked whether authoring-side checks deserved a higher-level split; the answer that growth gave is that the catalog now has at least four top-level modes (verify content / shape the work cycle / audit form & budget / maintain the corpus). The 2026-06-08 additions folded into existing clusters without a new mode, so the four-mode structure held — but /which-skill is now the only practical per-request entry point, and if the count keeps growing the map may need to become a map of cluster-maps.
  • Are Chain 1 and Chain 2 actually different chains, or is “AI-drafted” vs “self-drafted” a distinction without a difference once the artifact exists? Watch in practice; collapse if both behave the same.
  • Should /disagree move out of the adversarial cluster? It targets the last assistant turn, not an artifact. Currently grouped with /red-team because they share the inversion intent.
  • The code-review cluster routes by provenance (/lean-review any diff, /ai-diff-judgment AI-authored). As AI-authored becomes the default provenance, does the distinction collapse into cheap-vs-deep — and if so, does /lean-review survive as the cheap tier or fold into the built-in /code-review effort levels?
  • Chain 7 (full work cycle) is nine skills end-to-end; nobody will run it whole. Which two-or-three-skill sub-chains of it actually recur in practice? Log real usage before prescribing more.
