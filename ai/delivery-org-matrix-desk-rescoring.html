Desk Rows Re-scored — the Verification-Cost Axis Applied

delivery-org-agent-fit-matrix re-judgment #1 says the matrix models only one of three arguments: fit = f(task type, verification cost, blast radius). This note executes that re-judgment on the rows actually on this desk, using the machinery from human-role-roadmap-under-ai: the honest score is a rung (L1–L5) per workflow, set by how cheap an independent oracle is (a check the human didn’t author) and how large the aggregate blast radius is (per the roadmap’s aggregation caveat — individually-reversible actions can aggregate into consequential outcomes). Source data: delivery-org-task-matrix-data; row numbers refer to it.

Desk-row selection is an inference, not given by the source: the 21 rows below are what an architecture-owning lead-web-developer seat (TypeScript/JS) plausibly touches. The matrix’s PDFs advertise role tags but don’t render them per-row, so no source-side attribution exists to check against. Defensible variants of the cut exist (accessibility implementation, IaC, and production monitoring are arguable inclusions). That is one reason the findings below are stated as patterns, not counts. The headline, up front: under the two added columns no High keeps a single unconditional label — each splits by blast radius, holds only while an independence condition is maintained, or demotes.

Red-teamed same day (2026-07-17, clean-context pass); two corrections applied and kept visible below — the count-based headline was replaced with a pattern statement, and the oracle-layer demotion was rebuilt around governing independence rather than keeping authorship.

Method — the two added columns

  • Verification cost — cost of an independent oracle for the task’s output. Low means a check exists that the human didn’t author and that fails loudly (tests, types, contract suites, “the spike runs”). High means the only check is the human re-deriving the judgment, or feedback arrives months later, confounded.
  • Blast radius — aggregate consequence of an undetected failure, not per-action reversibility.
  • Re-score — the honest fit under both columns, stated as fit + rung. Δ marks the divergence from the matrix: = holds · ↑ promotes · ↓ demotes · ⇄ splits into cases the single label conflated.

In the table, the Matrix column carries the source’s original fit label — H for High, P for Partial.

The differences, marked — what the added axis systematically changes

Of the 21 desk rows the matrix scores 9 High / 12 Partial. Under the added columns, no High keeps a single unconditional label — every one splits by blast radius, holds only while an independence condition is maintained, or demotes. (The first draft stated this as a count: “1 of 9 Highs survives”. The same-day red-team broke that count on three fronts: the survival criterion was applied inconsistently across rows, the sole survivor’s blast-radius cell violated this note’s own definition, and the seat-relative row cut makes any count unstable — the same instability-under-re-slicing the parent note already warns about. The pattern statement is what survives.) The divergences sort into five patterns:

  1. The oracle layer cannot be delegated the way the matrix implies — the biggest single difference. The matrix scores CI/CD setup, test-case authoring, and automated-test implementation flat High: they are re-encoding, so by the matrix’s axis they’re maximally delegable. But these rows are the oracle infrastructure every other High’s re-score depends on, and what governs them is human-role-roadmap-under-ai’s independence requirement: the protecting check is one the output’s author didn’t write. So the demotion is conditional, not absolute — same-agent-writes-code-and-tests is self-undermining. The hollow-suite evidence — 100% coverage, 4% mutation score — shows that failure is real, not hypothetical. By contrast, cross-agent authorship under a verified mutation floor and seat-held required-checks config satisfies independence with no human authorship at all. What the seat must keep is governance of oracle independence — who checks whom, floors, sampling, escalation policy — not the authoring. (The first draft claimed authorship itself must stay with the seat; the red-team showed that contradicts the roadmap’s own definition of the protecting oracle, and the cited mutation-testing trajectory has agents driving the oracle layer as the mainstream direction.)
  2. The implementation Highs split rather than hold. Frontend, backend, database: H is true of the median reversible ticket and false of auth, payments, identity, write-path migrations — same task type, different blast radius, different honest rung. No row keeps a single unconditional label.
  3. Two promotions the matrix missed. Technical spike artifacts (self-verifying + throwaway; the feasibility inference stays human) and bug reproduction/clustering. Estimation is a third, conditional on running the calibration loop the vault already has — an owned feedback loop the matrix’s axis can’t see (delayed and scope-confounded, but scoreable, which is more than the other strategy Partials have).
  4. The strategy Partials hold but their moat gets re-labeled. Solution architecture, stack selection, schema design stay P — pinned at L2 not by tacit human skill but by oracle absence plus delayed feedback. That matters for durability: it makes them exactly the family-(b) forecast the parent note warns about (a moat resting on a capability claim, not a position). If verification tooling reaches architecture decisions (fitness functions, executable architecture tests), the pin releases and these rows drift toward the High column.
  5. Spec authoring demotes from High. The matrix reads “developer handoff & specs” as re-encoding decided design. But the spec is the one artifact with no external oracle — it is the source of intent that all other verification checks against, and writing it is the L2→L3 binding skill. Delegate the drafting; the intent must stay authored.

The compressed conclusion: on this desk, the matrix’s High column is really three different things — honest Highs (cheap oracle, contained blast radius: median tickets, spike artifacts, perf-test execution), conditional Highs (High only while an independence check holds: tests-with-mutation-floor, docs-with-sampling), and oracle-layer Highs (rows where the output is the checking infrastructure, so delegation is safe only under seat-governed independence — check-author ≠ output-author, plus meta-monitors). The single-axis matrix cannot distinguish them, and the third category is the dangerous one — it looks most delegable on the re-encoding axis while being exactly where ungoverned delegation is self-undermining.

What would revise this note

  • Architecture-level oracles maturing from constraint-guards (the Layer 5 fitness functions that already exist) into checks on the decision itself → the strategy Partials un-pin from L2; finding #4’s durability warning fires.
  • Agent-authored test suites with verified mutation floors becoming routine → the conditional Highs (#59, #60) collapse back to plain High, and finding #1 reduces to a governance checklist rather than a demotion.
  • Field evidence that sampled-review + escalation-policy regimes fail like uniform review does → the code-review restructure (#62) was a rearrangement, not a fix, and the rubber-stamping base rate wins regardless of structure.
  • The desk changing — the row selection is seat-relative and should be re-cut if the seat’s task mix shifts.
