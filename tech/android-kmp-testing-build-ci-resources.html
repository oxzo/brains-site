As of 2026-10-18 (subagent-verified that day). Toolchain state: Gradle 9.8.1, AGP 9.4.0 stable (9.5 preview), Kotlin 2.4.21.

Testing strategy

  • Fundamentals of testing — separates test scope (unit / medium / end-to-end) from where it runs (host vs device). Start here.
  • Testing strategies — the best single source for a many-team org. Five layers (Unit, Component, Feature, Application, Release Candidate), each with a network/execution/lifecycle policy; unit and component tests on every commit “for affected modules only”; recommends a written team testing-strategy document.
  • What to test — ViewModels, repositories, domain code; not framework behaviour; coverage isn’t the only metric.
  • Test doubles — official position: fakes are preferred.
  • Testing your multiplatform app — kotlin.test in commonTest; allTests runs every target; Android tests split into androidHostTest and androidDeviceTest.
  • Testing Compose Multiplatform UI — runComposeUiTest in common code across iOS, Android, desktop, Wasm. Experimental, and common tests can’t yet run via Android Studio’s local test configuration.
  • Test your Compose layout — Jetpack semantics, finders, assertions.
  • Now in Android — no mocking library; “Test” repository implementations swapped in via Hilt; Roborazzi screenshots recorded on Linux CI.

Architecture tests and static checks

  • Konsist — architecture rules as unit tests; supports KMP. Pre-1.0. Best for package-defined layers; leave module boundaries to the build.
  • detekt — stable 1.23.8 targets Kotlin 2.0.21; 2.0 is alpha on Kotlin 2.4. You run either stale-stable or alpha.
  • Android Lint — run ./gradlew lint in CI (not part of the normal build); baselines gate only new issues.
  • Dependency Analysis Gradle Plugin — Tony Robalik. buildHealth finds unused deps and wrong api/implementation; supports the KMP Android library plugin. Rationale: The proper care and feeding of your Gradle build (2020; 4–17% build gains in Square’s scenarios).
  • modules-graph-assert — allowed/restricted module dependency rules, max tree height, Graphviz export. Gradle 9 compatibility unconfirmed.

Gradle for a large codebase

Official docs:

  • Gradle Best Practices — an official section of 47 practices: Kotlin DSL, build-logic composite builds, convention plugins, version catalogs, build + configuration cache, avoid afterEvaluate, test build logic with TestKit. Read it end to end.
  • Sharing build logic — convention plugins; avoid allprojects {}/subprojects {}.
  • Version catalogs — gradle/libs.versions.toml.
  • Configuration cache — preferred since 9.0; “will be enabled by default in Gradle 10”.
  • Build cache — CI writes the remote cache, developers read it; declare path sensitivity so entries are relocatable.
  • Isolated Projects — incubating since 9.7; parallel configuration. Track it: configuration time grows with module count.
  • Performance guide + Gradle Profiler + free Build Scans (--scan). Develocity is the commercial tier.

Android / KMP specifics:

  • AGP release notes — AGP 9.4 needs Gradle 9.6+, JDK 17; AGP 10 makes the new Variant API mandatory.
  • Choosing a KMP project configuration — with several shared modules, export one umbrella iOS framework; multiple frameworks duplicate dependencies and break shared state.
  • Kotlin/Native target support — Apple binaries build only on macOS; this drives CI cost.
  • Improving Kotlin/Native compile time — keep ~/.konan cached in CI, build only needed targets, debug binaries in development (release links take roughly an order of magnitude longer), avoid transitiveExport.
  • NiA build-logic — a working convention-plugin set: additive, composable, single-responsibility.

Scale case studies (Square — figures quoted from the posts):

  • Herding Elephants — Tony Robalik (2021-11-04). ~3,500 modules, ~2M lines of Kotlin. Treat build code as production code; test it with TestKit; avoid buildSrc. Included builds added ~30 s (~33%) to configuration, so Square published build logic as binary plugins — a counterpoint to Gradle’s “favour composite builds”.
  • Stampeding Elephants (2023-01-31) — ~4,400 modules, IDE sync up to 30 GiB memory; configuration cache saving an estimated 5,400+ developer-hours/year; Square’s Bazel attempt for Android didn’t pay off.
  • Supercharging CI with Gradle (2023-07-27) — 1,200 CI shards, ~600 skipped on average via change-based avoidance: the “affected modules” idea built in-house.
  • Evolution of Developer Productivity, Part Two (2024-01-29) — configuration cache: local builds up to 50% faster; Bazel helped iOS (−80%) and Java (−30%) but not Android. Code review, not build speed, was named the main bottleneck.

Alternatives: Bazel (rules_kotlin, rules_android — “development preview”) has no stated KMP/Kotlin-Native iOS story; Grab’s Grazel migrates Gradle→Bazel incrementally. For a KMP app, Gradle is the only mainstream option.

CI/CD

  • gradle/actions (setup-gradle) — the standard GitHub Action. Its default “Enhanced Caching” is proprietary (free preview for private repos); cache-provider: basic is MIT. Check terms for an enterprise private repo.
  • GitHub runner images — macos-latest is macOS 26 arm64; pin the label instead.
  • Gradle Managed Devices — emulator groups and sharding from Gradle; needs swiftshader_indirect GPU on runners without hardware rendering.
  • Fastlane — supply for Play uploads and track promotion; also the common bridge for iOS release. Supports Workload Identity Federation from GitHub Actions.
  • Gradle Play Publisher — tracks, staged rollouts (userFraction), promotion; maintenance mode.
  • App size: Emerge Tools was acquired by Sentry (May 2025); Sentry now offers Size Analysis. The Emerge Gradle plugin’s future is unconfirmed.

Test pyramid for a KMP app (synthesis)

Mapped from Android’s five-layer strategy, the KMP test docs, NiA and the screenshot-tool READMEs — the mapping to KMP is this note’s synthesis, not one source.

  1. Unit (most numerous) in commonTest — domain, ViewModels, Flows with kotlin.test + runTest + Turbine; fakes first, Mokkery only where a fake is impractical. Every commit, affected modules only.
  2. Component — Robolectric for Android-specific code; runComposeUiTest (experimental) or createComposeRule; Roborazzi/Paparazzi screenshots. iOS screenshot coverage is weak.
  3. Feature — components wired together with fakes, pre-merge; include the umbrella-framework boundary.
  4. Application — post-merge on emulators (Gradle Managed Devices) and iOS simulators on macOS runners; navigation and critical-flow regression tests.
  5. Release candidate — end-to-end on a minified release build, nightly and pre-release, on a device matrix (Android suggests phone/foldable/tablet nightly; 8 phones + 1 foldable + 1 tablet pre-release). Firebase Test Lab’s shutdown lands here.
  6. Alongside: Konsist, detekt, lint, DAGP, module-graph rules.

Build-health checklist

  1. Pin and regularly upgrade the Gradle wrapper; validate it on upgrade (Gradle best practices).
  2. Kotlin DSL everywhere.
  3. One version catalog.
  4. Build logic in single-responsibility convention plugins; no subprojects {} — and measure included-build configuration cost (Square).
  5. Configuration cache + build cache on (default in Gradle 10).
  6. Remote cache: CI writes, developers read; relocatable task inputs.
  7. Test build logic with TestKit across a Gradle/AGP matrix.
  8. DAGP buildHealth in CI.
  9. Enforce module boundaries (modules-graph-assert or Konsist); avoid over-granular modules.
  10. Benchmark build changes with Gradle Profiler + Build Scans.
  11. Affected-only unit/component tests per commit.
  12. Cache ~/.konan, build only needed K/N targets, debug binaries in dev.
  13. Track Isolated Projects.
  14. Plan for AGP 10: built-in Kotlin, KMP Android library plugin, no kapt.
  15. Deterministic screenshot goldens: record and verify on the same OS.

Tradeoffs

  • build-logic vs buildSrc vs published plugins — Gradle favours composite builds; Square measured them costing configuration time and published binaries instead. Measure your own.
  • Fakes vs mocks — fakes are the official preference but cost maintenance; Mokkery is the only common-code mocking option and is young.
  • Module granularity — Square runs thousands of modules and pays in sync memory; Google warns against over-granularity; the iOS umbrella framework means iOS consumes every shared module together anyway.
  • Tool churn — AffectedModuleDetector archived, Amper renamed, Test Lab ending, GPP in maintenance, detekt 2.0 alpha, Konsist pre-1.0. Pin versions and keep an exit path.
  • Free vs commercial — Build Scans free, Develocity commercial; setup-gradle’s default cache proprietary.
